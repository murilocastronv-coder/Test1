# PixelLab Runtime Helpers

Turns exported maps into the running game (load, render, collide, spawn, warp). The contract boundary: these helpers already absorb the fiddly parts of the export format, so a scene that parses the JSON itself re-derives dual-grid sampling, transition tiles and warp rects. Rendering is `renderMap.ts` + `terrainRenderer.ts` (there is no `MapRenderer.ts`). `assets/maps/{id}/` is regenerated by asset sync, so edits there are reverted rather than rejected — a map task is nearly always wiring, not regenerating terrain.

- **Map swap:** one line — `MAP_FOLDER` in `templateAssetPaths.ts`. The runtime already handles bounds, tilesets, overlays, objects, spawns, and collision. Explicit `@map [id:...]` → read `assets/maps/{id}/map.json` (+ `annotations.json` when `map.json.gameplayAnnotations.file` is set; `objects/manifest.json` before moving objects). `assets/manifest.json` = name→path.
- **Multi-map:** go through `mapHelpers.ts` so preload/render/spawn/camera share one `LoadedMap` — mixing new-map JSON with old texture keys is the usual broken-warp cause. `renderMap(...)` tears down the previous map itself.
- **Warps:** `switchPlayerToMap(scene, targetMapId, player, currentRenderedMap)`; `{ spawnName }` for an entry point; `this.agents = replaceNpcs(this.agents, [])` after. Map-editor areas → `switchPlayerByWarpArea(...)` (`mapWarps.ts`) with `player.worldPosition`, following rect `targetMapFolder`/`targetMapId`/`targetSpawnName`; keep those areas non-blocking. The target `LoadedMap` drives everything after, so patching via `TEMPLATE_SPAWNS` or tile offsets just relocates the bug.
- **Rooms (`create_room`):** the project's rooms sync to `assets/rooms/<id>/` (`room.png` + `metadata.json`; `projectRoomUrl(id)`), and `list_rooms` lists every room by id. The metadata (and `get_room`) gives each door's `anchor` (set rooms wall to wall: B's top-left = A's + A's anchor − B's), `trigger` and `arrive`, and the walkable rects (collision: walls, back doors included, are not walkable). Collide with `roomBlockers(rooms)`: every wall exactly (pictures minus walkable areas) as blocker rects, never walls guessed by hand (they let the player stand on a wall top). Run them with `startRoomCamera(scene, rooms, player.sprite, { lerp: GAME_CONFIG.camera.followLerp, footOffsetY: GAME_CONFIG.player.footOffsetY, facing: () => player.facing, place: (x, y) => player.teleportTo(x, y) })` (`roomCamera.ts`) in place of the follow camera, `.update()` every frame: each room is `{ name, x, y, width, height, doors, areas, objects }` (metadata `doors` as is, walkable rects moved to where it stands, the sprites to show only in it). It zooms each room to the largest whole number that fits it on screen, links doors whose anchors meet, and when the player steps into a door's trigger fades to black, calls `place(x, y)` with the other door's arrive point and fades back into that room alone. Never show the room left behind beside the next one, or let the player walk over a painted door (both looked bad to users). Hold the player's input between `onTransition`'s "start" and "end".
- **Spawns:** `spawns.ts` only (keeps collider + fallbacks consistent). Roles from point/layer names+tags (`player spawn`, `npc spawn`, `farmer spawn`, `bear spawn`), then `TEMPLATE_SPAWNS` (default map only). `resolvePlayerSpawnPoint(mapData)`, `resolveWalkableSpawnPoint(...)` (snaps to walkable), `resolveMapEntryPoint(mapData, {spawnName})`.
- **Collision:** `collision.ts` (+ `shared/collision.ts`). `annotations.json` layers are authoritative: terrain-source layers set base allow/block, then `rects`/`cells` override — honor both. Infer from layer/terrain NAMES (`water`/`wall`/`lava`/`cliff` block; `grass`/`ground`/`path`/`floor` allow) — matching one exact string works on the map in front of you and silently stops working on the next one the user generates. `map.json.walkableTerrainIds` = fallback for old maps; `terrain-map.json` is layout, not a collision knob.
- **Coordinates:** Y-down world pixels, same as the editor (no center-origin/Y-up). Terrain dual-grid: tile `(x,y)` samples cells `(x-1,y-1),(x,y-1),(x-1,y),(x,y)`, centered on `x*tileSize`. Terrains that no one tileset spans (tilesets made separately) meet with a straight hard edge, each quarter cut from its corner's plain tile — intended, not a rendering bug; a tileset connecting the two blends it. Objects/overlays/spawns/rects are already in exported pixels, so an offset is a sampling or texture-key/preload issue — half-shifting them breaks every aligned map.
- **Projected tile-layers (iso/oblique/hex):** `tile-layers.json` + `tile-layers/` render/elevate/depth-sort/collide via `tileLayers.ts` automatically, so a swap is still just `MAP_FOLDER` (a custom tilemap fights it). Unpainted = void, structure layers = walls, corner-wang materials decide the rest. Step up/down within `GAME_CONFIG.terrain.maxStepUp`/`maxStepDown` (`config.ts`, default 1; 0 = walls). Change a material via `MATERIAL_WALKABILITY_OVERRIDES` in `config.ts`. Geometry scales from the group's export — no per-tileset constants. `annotations.json` collision still overrides.

**Export files:** `map.json` (config/tiles/bounds/terrains/tilesets/overlays/walkable-fallback/annotation-pointer) · `terrain-map.json` (layout) · `tile-layers.json`+`tile-layers/` (projected) · `tilesets/*.png` · `objects/manifest.json` (filenames+boxes) · `annotations.json` (spawn/collision/trigger/hazard/custom) · `transition-map.json`/`transition-rules.json` (renderer debug; `transitionSize=1` → synthetic terrain where `baseTileId == "transition-{tilesetId}"`).

Green/black tiles = missing texture: check `loadPixelLabMap`/`preloadMapAssets`/`renderMap` share one `LoadedMap.folder`. `map-composite.png` is reference art only (nothing renders it; missing textures throw).
